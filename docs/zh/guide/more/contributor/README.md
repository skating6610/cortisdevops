# 贡献者

感谢所有参与 cortisdevops 项目建设的社区成员。无论是提交代码、完善文档、反馈问题、验证部署、分享实践，还是提出产品建议，都是推动项目持续改进的重要贡献。

## 我们认可的贡献方式

- 提交功能代码、问题修复或重构优化
- 补充安装部署、使用说明、FAQ 和最佳实践文档
- 反馈 Bug、兼容性问题和安全风险
- 验证 Docker Compose、Kubernetes Helm 等部署方式
- 完善示例配置、脚本和运维流程
- 参与 Issue 讨论，帮助其他用户定位问题
- 提出产品能力、交互体验和工程治理建议

## 贡献记录

为了让贡献记录更加客观、可追踪，项目后续主要通过以下方式记录贡献：

- Git 提交历史
- Pull Request 记录
- Issue 讨论记录
- 版本发布说明
- 文档更新记录

贡献者名单不再按个人排名展示，也不再区分“核心贡献”“文档贡献”等固定身份。感谢每一位参与者在不同阶段对项目做出的投入。

## 如何参与

1. Fork 项目仓库并创建独立分支。
2. 保持每次改动目标清晰，避免混合多个无关变更。
3. 提交前运行相关测试、构建或文档检查。
4. 在 Pull Request 中说明修改背景、解决的问题和验证方式。
5. 如果涉及权限、凭证、任务执行、Agent、网关等能力，请额外说明安全影响和边界。

## 写在最后

cortisdevops 希望成为一个长期可维护、可扩展、对企业运维场景真正有帮助的开源项目。欢迎更多同学参与建设，一起让 DevOps 与自动化运维变得更简单、更可靠。
